* cs.DB (Databases)

** 🧐 Обзор
За последние сутки заметен устойчивый сдвиг к «ML-инфраструктуре для СУБД»: learned-индексы выходят из статичной постановки в адаптивные и обновляемые сценарии (FLAIRS/TULSI, STARR для миграции HNSW), а LLM встраиваются в потоковые пайплайны и подготовку данных (Continuous Prompts, ShapleyPipe). Отдельно зреет тема корректности агент-генерируемых data pipeline — ArrivalBench показывает, что одноразовое тестирование пропускает до 79% молча некорректных пайплайнов. Практически значимы также системы интерпретируемой автоматизации (ShapleyPipe) и ИИ-конструирование маршрутов с ограничениями (CRAFT).

** 🛠 Практика и Системы
- [[https://arxiv.org/abs/2508.03471][Learned Adaptive Indexing with Updatable Learned Index]]
:WHAT: FLAIRS — первый learned-индекс для адаптивного индексирования, достраивающийся на лету из запросов, с обновляемым learned-индексом TULSI и предсказанием рабочей нагрузки.
:IMPACT: Убирает главный барьер learned-индексов — необходимость полной перестройки при тяжёлых обновлениях и смене workload; даёт выигрыш по памяти и времени запросов без B+-tree.
- [[https://arxiv.org/abs/2510.27168][ShapleyPipe: A Game-Theoretic Approach to Data Preparation Pipeline Construction]]
:WHAT: Формулирует конструирование пайплайнов подготовки данных как кооперативную игру и вводит позиционно-зависимую метрику вклада операторов PipeShapley; иерархическая версия H-SP с MAB и ранней остановкой делает это практичным.
:IMPACT: Даёт интерпретируемый и позиционно-осознанный выбор операторов вместо перебора; Pareto-оптимален по accuracy/runtime, масштабируется до 581K записей.
- [[https://arxiv.org/abs/2512.03389][Continuous Prompts: LLM-Augmented Pipeline Processing over Unstructured Streams]]
:WHAT: Первая система (VectraFlow), встраивающая LLM-рассуждение в непрерывную потоковую обработку: непрерывные семантические операторы, RAG для стримов, батчинг/фьюжн операторов и динамическая оптимизация через MOBO и shadow-исполнения.
:IMPACT: Превращает stateless LLM-фреймворки в долгоживущие аналитические пайплайны с управляемым trade-off throughput/accuracy — ключевой шаг к семантическому мониторингу неструктурированных потоков.
- [[https://arxiv.org/abs/2611.25416][Standardized Tolerance for Adaptive Reuse and Repair: A Method for HNSW Migration Under Embedding Model Change Scenarios]]
:WHAT: STARR — метод миграции HNSW-индексов при смене embedding-модели: переиспользует рёбра исходного графа по корреляции стандартизованных длин рёбер и выполняет финальный ремонт достижимости.
:IMPACT: Медианный ускоритель построения 16.7x с потерей recall всего ~1 п.п. — прямая экономия на переиндексации миллиардных векторных коллекций при смене модели.
- [[https://arxiv.org/abs/2610.02363][ArrivalBench: Agent-Generated Data Pipelines Are Correct Once and Wrong Under Time]]
:WHAT: Бенчмарк, оценивающий пайплайны не разовым запуском на снапшоте, а повторным исполнением при повторяемых adversarial-расписаниях доставки (дубликаты, задержки, out-of-order) с рекалькуляцией оракула.
:IMPACT: Показывает, что 7–79% пайплайнов, «прошедших» обычный тест, молча некорректны — меняет практику CI/CD для агент-генерируемых данных и отделяет crash от тихой порчи данных.
- [[https://arxiv.org/abs/2611.25128][CRAFT: Constrained Route planning with Adaptive Framework and Template-based code generation]]
:WHAT: LLM-фреймворк, переводящий текстовый запрос с ограничениями (остановки, EV-зарядка, бюджеты) в генерируемые поисковые функции над графовым движком; формализация SE-RCSP с неаддитивными состояниями.
:IMPACT: Закрывает практический разрыв «один солвер — один тип запроса»: единый движок покрывает класс реальных маршрутов на дорожных сетях.

* cs.DC (Distributed Computing)

** 🧐 Обзор
Доминирует оптимизация памяти и изоляции для LLM-сервинга: трансформации KV-кэша (Gemma 4 Global-KV, Twindex), иерархия HBM–flash, прозрачная memory oversubscription (TRANSIT) и SLO-безопасное GPU-шаринг без патчей драйверов (Berth). Параллельно зреет тема устойчивой балансировки скошенных потоков событий — CheckCo из production-системы даёт imbalance 1.10 против 8.03 у key-based routing. В HPC-сегменте трёхпоточное перекрытие в pipelined Krylov-методах даёт до 1.33x на 64 GPU.

** 🛠 Практика и Системы
- [[https://arxiv.org/abs/2611.22476][CheckCo: Checkpoint-Coordinated Load Balancing for Skewed Event Streams at Scale]]
:WHAT: Алгоритм балансировки с координацией через checkpoint-барьеры: динамический оракул оценивает частоты ключей из живого потока, делит «горячие» ключи на сплиты и пакует их на воркеров на следующем окне.
:IMPACT: В production-пайплайне на 100+ млрд событий/день сжимает дисбаланс до 1.10 при вдвое меньшем fan-out — решает типичную проблему hot-key skew в стриминговых системах (Flink/Spark-класса).
- [[https://arxiv.org/abs/2611.25091][Berth: SLO-Preserving GPU Sharing Without New Preemption]]
:WHAT: User-space система, добивающаяся приоритизации latency-чувствительных запросов над best-effort задачами через feed control и укороченные time slices встроенного планировщика GPU — без изменения приложений, ядер и драйверов.
:IMPACT: Позволяет заполнять простой GPU-ресурса обучением при сохранении SLO; 2.7–3.5x throughput best-effort — прямая экономия на закрытых GPU-стеках, куда оператор не может залезть.
- [[https://arxiv.org/abs/2611.25078][Twindex: Index Cache Offloading with Coarse-to-Fine Selection for Long-Context Sparse-Attention Serving]]
:WHAT: Выгружает кэш индексатора sparse-attention моделей в host-память, оставляя в HBM компактную копию (shared компонент + сжатые остатки) для грубой фильтрации кандидатов; работает внутри CUDA graphs.
:IMPACT: Устраняет неожиданный узкий кэш-бутылочное горлышко (63–75% HBM на 1M токенов) и вмещает до 3x больше запросов на GPU — критично для долгоконтекстного инференса.
- [[https://arxiv.org/abs/2611.23035][Storing the Gemma 4 K=V Cache Once: Exact Global-KV Memory Savings in a Paged Serving Engine with Unchanged Attention Kernels]]
:WHAT: Хранит один 640-значный ряд вместо полного key+value (1024 значения) для global-attention слоёв Gemma 4, читая кэш через два перекрывающихся strided views без изменения attention-кернелов.
:IMPACT: Сжатие KV-памяти decode в 1.34–1.40x и рост decode throughput до 1.38x при побитовой идентичности выхода — готовое к интеграции в vLLM-класс движков.
- [[https://arxiv.org/abs/2610.07593][TRANSIT: Transparent Scale-in for Multi-Node LLM Training]]
:WHAT: Система прозрачной memory oversubscription для distributed LLM-тренировки: координация page residency драйвера с zero-copy доступом по паттернам итераций.
:IMPACT: Тренировка на до 50% меньше GPU с сохранением >90% throughput и снижением межузлового трафика до 33% — прямой капекс-выигрыш для кластеров.
- [[https://arxiv.org/abs/2609.39131][Characterizing High Bandwidth Flash for LLM Serving]]
:WHAT: Иерархическая система HBM–HBF (high-bandwidth flash) с buffered cache-aware планированием для agentic-сервинга, с анализом энергии и write lifetime.
:IMPACT: Сокращение completion time на 21–87% и продление срока жизни flash с 0.99 до 13.6 лет — задаёт инженерную рамку для использования HBF как активного яруса памяти.
- [[https://arxiv.org/abs/2610.24830][HEL: A Heterogeneous Extensible Layer for GPU-Resident Runtime Orchestration]]
:WHAT: GPU-resident рантайм с персистентными сервисами, корутиноподобными задачами, зависимостями и автоматическими retry; приложение и задачи работают на пространственно разделённом GPU.
:IMPACT: Обобщает исполнение задач на GPU как на ЦП — выигрыш на недоутилизированных GPU и скрытие латентности задач.
- [[https://arxiv.org/abs/2610.25058][Triple Overlap in Pipelined Krylov Methods on Multi-GPU Systems]]
:WHAT: Трёхпоточная реализация Pipe-PCG/Pipe-BiCGStab: одновременное исполнение коллективов, P2P-связи и вычислений на нескольких GPU.
:IMPACT: Геом. ускорение 1.23–1.33x против two-stream на 64 GPU и до 3.27x над PETSc — прямой эффект для масштабируемых научных вычислений.
- [[https://arxiv.org/abs/2608.11770][Achieving Near-Zero-Overhead Multi-Model Hierarchical Classification in Real-Time Detection Pipelines]]
:WHAT: Методика INT8-деплоя классификационных backbone на NVIDIA Jetson DLA (включая workaround для implicit quantization, ONNX graph surgery) и конкурентный GPU-детекция / DLA-классификация пайплайн.
:IMPACT: Near-zero overhead (12.5 vs 13.3 FPS) для иерархических детекция+классификация конвейеров на edge — обобщается на любые detection-classification пайплайны.

- [[https://arxiv.org/abs/2505.10006][Improved Rank Aggregation under Fairness Constraint]]
:WHAT: (2+ε)-аппроксимация для fair rank aggregation по Kendall tau, улучшающая прежнюю 3-аппроксимацию, плюс 2.881-аппроксимация, не зависящая от конкретной метрики справедливости.
:IMPACT: Напрямую применимо к поиску, подбору персонала и БД-ранжированию, где нужна гарантированная репрезентативность групп в top-k.

:IMPACT: Фундамент для рекомендательных систем с slate-интерфейсами: оптимальное число запросов для обучения модели выбора на ограниченном трафике.

* physics.soc-ph (Social Physics & Networks)

** 🧐 Обзор
Тренд — переход от бинарных к взвешенным и higher-order сетевым моделям: multiscale renormalization и reconstruction распространены на взвешенные сети, а higher-order функциональные зависимости выводятся как гиперрёбра из event time series. Параллельно зреет tooling для геометрии сетей: персистентная A-гомотопия и Ricci flow с хирургией на финансовых корреляционных графах. Практически релевантно: восстановление крупноузловых сетей (международная торговля, производственные сети) на уровнях агрегации без переобучения параметров.

* cs.AI (Artificial Intelligence)

** 🧐 Обзор
В сутки тренд смещается от чистых LLM-бенчмарков к системной интеграции ИИ в критические контуры: защита collaborative perception (CP-Guard+), LLM-обнаружение угроз в IoT, устойчивое планирование траекторий при дисбалансе данных (FlowDrive) и forecasting для нерегулярных временных рядов (FlexTSF). Развивается и методологический слой — TELEVAL показывает, что высокие метрики задач не гарантируют надёжность spoken-взаимодействия, а работа про mechanistic interpretability призывает к философскому контролю понятий MI.

:IMPACT: Снижает вычислительные издержки детекции атак и закрывает ключевую уязвимость V2X/коллаборативного восприятия для автономного вождения.

:IMPACT: Практичный шаблон edge-cloud защиты IoT с объяснимыми и адаптивными мерами противодействия.

:IMPACT: Прямо применим к мониторингу систем и telemetry с гетерогенной частотой сэмплирования — типичная ситуация для observability-пайплайнов.
