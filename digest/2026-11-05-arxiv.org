* Базы данных (cs.DB)
** 🧐 Обзор
Главный тренд дня — возвращение инвариантов и ускорителей на уровень самой СУБД: JetStream генерирует верифицированные query-ускорители поверх существующих движков, а «constraint indexes» вновь делают целостность обязанностью базы в мире LLM-агентов с одноразовым кодом. Зреет производительный слой индексов и структур: PiPNN II строит миллиардные k-NN графы за минуты, COL-Trees на порядки ускоряет поиск объектов в дорожных сетях. Практически значимы также осмысленный выбор источников в data lake'ах (Splice) и экономная по памяти реализация гиперграфовой дуализации для D-basis.

** 🛠 Практика и Системы
- [[https://arxiv.org/abs/2610.20527][JetStream: Generating Verified Query Accelerators for Existing Database Systems]]
:WHAT: Агентный пайплайн, синтезирующий query-специфичные ускорители поверх существующей СУБД: «протестированные» (дифференциальное тестирование) и «верифицированные» (машинно-проверяемое доказательство по спецификации из SQL) варианты, с engine-neutral substrate для транзакционной согласованности auxiliary state при записи.
:IMPACT: На TPC-H SF=20 — ускорение чтения до 584× против DuckDB (89× для верифицированных) с сохранением 139× при потоке обновлений 10 тыс. строк/с; без миграции данных и без отказа от ad-hoc запросов.

- [[https://arxiv.org/abs/2610.36418][When the Application Layer Is Disposable: Putting Integrity Constraints Back in the Database]]

:IMPACT: Восстанавливает инварианты на уровне БД именно тогда, когда LLM-агенты генерируют и выбрасывают код, пишущий напрямую в базу: до 2.41× быстрее лучшего сохраняющего корректность baseline; показано, что LLM-писатели регулярно нарушают неотслеживаемые ограничения.

- [[https://arxiv.org/abs/2601.20482][ConStruM: A Structure-Guided LLM Framework for Context-Aware Schema Matching]]
:WHAT: Структурно-ориентированный фреймворк бюджетной упаковки свидетельств для schema matching: context tree для многозиходового retrieval и глобальный similarity-гиперграф для разделения «путающихся» колонок; работает как add-on над upstream-матчером.
:IMPACT: Средняя точность 95.4% против 51.6% у LLM без контекста на HRS-B/PSID-B, первое место среди 11 методов; на MIMIC-OMOP/Synthea-OMOP не ухудшает сильный baseline.

:IMPACT: +1.8–13.7 пунктов utility на пяти реальных ML-задачах против «взять все таблицы» и +3–5 п.п. F1 на union-search бенчмарках, при 3–7× (до 77×) меньшем числе модельных оценок.

:WHAT: GPU-резидентный пайплайн LLM-сжатия, устраняющий «execution redundancy» (host-передачи per-token, CPU-side coding) через batch-invariant ядра, плюс характеризация trade-off'ов спекулятивного dual-model и multi-token single-model кодирования.
:IMPACT: Ускорение арифметического кодирования до 5.8× при encoding и 3.0× при decoding без изменения коэффициента сжатия — шаг к практической применимости LLM-компрессоров.

* Структуры данных и алгоритмы (cs.DS)
** 🧐 Обзор
Динамические графовые алгоритмы дают первый по-настоящему tight результат: recourse динамической (Δ+C)-раскраски закрыт для широких палитр с помощью новой техники shift-tree. Онлайн-алгоритмы выходят на системную мотивацию — кэширование соединений в matchings для оптических коммутаторов SDN с почти совпадающими верхними и нижними оценками. Фундаментальные структуры данных тоже продвинулись: нижняя оценка 2 для Greedy-Future в динамических BST и опровержение LP-гипотезы для search trees on trees.

** 🕸 Графы и Алгоритмы
- [[https://arxiv.org/abs/2602.09497][Beyond Vizing Chains: Improved Recourse in Dynamic Edge Coloring]]
:ALGO: Техника shift-tree, отслеживающая множество возможных перекрасок динамического графа; tight recourse O(log n / log((Δ+C)/(Δ−C))) при C ≥ 0.62Δ и улучшение для графов низкой arboricity (C ≥ (2+ε)α−1).
:IMPACT: Первый детерминированный алгоритм с tight bounds для широких палитр (и первый при Δ−C=o(Δ)); динамическая раскраска — базовый примитив для планирования и распределения ресурсов в графовых системах.

- [[https://arxiv.org/abs/2310.14058][Caching Connections in Matchings]]
:ALGO: Онлайн-задача caching in matchings для k непересекающихся по вершинам наборов соединений: детерминированный O(nk)- и рандомизированный O(n log k)-конкурентный алгоритмы с почти совпадающими нижними оценками; качественное отделение от connection caching.
:IMPACT: Прямая мотивация — конфигурируемые оптические коммутаторы в SDN; показано, сколько «лишних» matchings нужно, чтобы конкурентность перестала зависеть от размера графа.

- [[https://arxiv.org/abs/2303.04199][Diversity Embeddings and the Hypergraph Sparsest Cut]]
:ALGO: ℓ₁-вложения diversities (обобщение метрик с пар на подмножества) с искажением O(log n) для diameter diversities; на их основе — полиномиальная O(log n)-аппроксимация hypergraph sparsest cut, когда supply или demand заданы графом.
:IMPACT: Улучшение лучших известных аппроксимаций для разрезов гиперграфов (против O(log(kn) log n) у Plotkin et al.) — ключевого примитива кластеризации и секционирования; попутно нижняя оценка n^{1−ε} для общих diversities.

- [[https://arxiv.org/abs/2301.03084][Dynamic Binary Search Trees: Improved Lower Bounds for the Greedy-Future Algorithm]]
:ALGO: Нижняя оценка 2 на конкурентность Greedy-Future и аддитивный разрыв с OPT порядка Ω(m·log log n) — через геометрическую модель (Geometric Greedy).
:IMPACT: Существенно продвигает гипотезу динамической оптимальности BST — фундаментальный вопрос для поисковых структур, лежащих в основе индексов и кэшей.

- [[https://arxiv.org/abs/2501.17563][Search Trees on Trees via LP]]
:ALGO: Опровержение гипотезы Голинского об интегральности LP-релаксации для search trees on trees («normals method», перечисление вершин политопа для всех деревьев до 8 узлов); нижние оценки integrality gap и approximation ratio.
:IMPACT: Уточняет, где искать полиномиальные алгоритмы оптимальных STT — структур, обобщающих BST на поиск по произвольным древовидным топологиям.

* Распределённые вычисления (cs.DC)
** 🧐 Обзор
Доминирует LLM-инфраструктура: TokenScale вводит проактивное автомасштабирование PD-дизагрегации по «token velocity», HYPIC переносит position-independent кэширование на hybrid-attention модели, а онлайн co-training draft-моделей ускоряет RL post-training до 2.25×. Зреет направление консенсуса с частичным доверием: Raftel объединяет TEE- и не-TEE-реплики в едином BFT-протоколе с реализацией на SGX. Практическую нишу закрывает RCOMPSs — task-based рантайм для параллельного R на manycore-системах.

** 🛠 Практика и Системы
- [[https://arxiv.org/abs/2512.03416][TokenScale: Timely and Accurate Autoscaling for Disaggregated LLM Serving with Token Velocity]]
:WHAT: Автомасштабирование prefill/decode-дизагрегированного serving: метрика Token Velocity, унифицирующая prefill, сеть и decode как опережающий индикатор backpressure, плюс Convertible Decoders — decoder-GPU, динамически выполняющие prefill при всплесках.
:IMPACT: SLO attainment растёт с 50–88% до 80–96%, стоимость снижается на 4–14% против DistServe, BlitzScale и AIBrix на кластере с production-трейсами.

- [[https://arxiv.org/abs/2607.01299][HYPIC: Position-Independent Caching for Hybrid-Attention LLM Serving]]
:WHAT: Первая система position-independent KV-кэширования для hybrid-attention моделей: кэширование segment-cumulative transition operator для linear-attention слоёв, «seam window» для ремонта cross-segment attention в full-attention слоях и segment parallelism для cold-запросов.
:IMPACT: TTFT снижается в 3.25× в среднем, QPS растёт в 1.66× против Prefix Cache при почти сохранённом качестве — критично для RAG и агентных пайплайнов с длинными составными промптами.

- [[https://arxiv.org/abs/2609.09742][Breaking Fault Lines: Unifying TEE-Assisted BFT Consensus in Partially Trusted Worlds]]
:WHAT: Raftel — первый HotStuff-подобный BFT-протокол для произвольных partial-TEE развертываний: dual-quorum конструкция (TEE-only + смешанные кворумы), TEE-leader fast path с аппаратным non-equivocation и tight resilience bound f < max{n/3, m/2}; pipelined-вариант chained-Raftel.
:IMPACT: До 625 TPS и <670 ms в WAN на Intel SGX, превосходя HotStuff на 308 TPS; практический путь гибридных развертываний, где TEE есть не у всех реплик.

- [[https://arxiv.org/abs/2505.06896][RCOMPSs: A Scalable Runtime System for R Code Execution on Manycore Systems]]
:WHAT: Task-based рантайм для параллельного исполнения R: пользователь пишет последовательный код, рантайм автоматически выполняет асинхронные задачи, отслеживает зависимости и планирует по ресурсам.
:IMPACT: Strong/weak scalability до 128 ядер на узел и 32 узлов (Shaheen-III, MareNostrum 5) для KNN, k-means и линейной регрессии; параллельная эффективность >70% в большинстве конфигураций.

- [[https://arxiv.org/abs/2609.07108][Online Draft Co-Training for Speculative Decoding in Large-Scale, Long-Context RL Post-Training]]
:WHAT: Онлайн co-training draft-модели с эволюционирующей policy в NeMo-RL под context/pipeline parallelism: merged zigzag ring attention (branch + causal main-sequence) для CP и TapChannel для транспорта таргет-фич между PP-стадиями.
:IMPACT: 1.48–2.25× ускорение rollout'ов и 1.19–1.88× end-to-end на моделях до 122B; strong scaling на длинах 256K с экономией памяти.
