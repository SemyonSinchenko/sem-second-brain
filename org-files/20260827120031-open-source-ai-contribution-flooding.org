#+title: Open source: AI contribution flooding
#+ROAM_REFS: https://neilalexander.dev/2026/06/30/flooding-contributions

* Summary
Source: [[https://neilalexander.dev/2026/06/30/flooding-contributions][https://neilalexander.dev/2026/06/30/flooding-contributions]]
Open source maintainers are experiencing a surge in AI-generated contributions, including pull requests and security vulnerability reports, designed to game GitHub contribution metrics rather than meaningfully improve projects. This trend undermines trust and forces maintainers to become more selective about accepting external contributions.

* Key Takeaways
- GitHub contribution graphs are used as hiring signals, incentivizing developers to pad profiles using AI.
- Maintainers observe an increase in trivial PRs (e.g., typo fixes) and security reports generated by LLMs without genuine project engagement.
- Accepting low-value AI contributions sets a bad precedent; trust and meaningful improvement matter more than metrics.

* Notes
** The Shift in Contribution Patterns
Maintainers report receiving far more pull requests than issues compared to the past. When issues are raised, they often include AI-generated analysis. Security vulnerability reports have also increased, frequently accompanied by AI-generated fix proposals. While some contributors are genuine, many appear to be using tools to create the illusion of engagement.

** AI-Driven Metric Gaming
It has become easy to instruct an [[id:96a58b04-1f58-47c9-993f-551994939252][LLM]] to find open source projects, identify trivial problems, and raise PRs to fix them. 
- Example: A contributor with no prior history submitted three PRs fixing spelling mistakes in comments.
- The commits were signed off by the user but included AI co-authorship trailers.
- The changes were harmless but materially improved nothing, serving primarily to add green squares to the user's activity graph.

** Maintainer Response
- Trivial PRs are being closed without comment to avoid encouraging busywork.
- Security reports are being evaluated more strictly; CVE notices may be declined for low-severity items to reduce coordination overhead.
- The core value of open source is trust, not the volume of automated contributions.
