#+title: AI-generated code should be Open Source
#+ROAM_REFS: https://jakub.jankiewicz.org/blog/ai-code-open-source/
#+filetags: :article:

* Summary
Source: [[https://jakub.jankiewicz.org/blog/ai-code-open-source/][https://jakub.jankiewicz.org/blog/ai-code-open-source/]]

The author argues that all code generated by AI should be released under Open Source licenses or dedicated to the public domain (e.g., via CC0). The case rests on two pillars: an *ethical* argument — [[id:96a58b04-1f58-47c9-993f-551994939252][LLM]] models were trained on decades of scraped Open Source code and CC-licensed Stack Overflow content without permission or attribution, so closing the output amounts to "license laundering" — and a *legal* argument — purely AI-generated code lacks human authorship and therefore should not be copyrightable, following the Monkey Selfie precedent later cited by the U.S. Copyright Office.

* Key Takeaways
- AI models were trained on a massive corpus of Open Source code scraped from the internet without permission or proper attribution; converting this collective knowledge into proprietary, closed-source code is /license laundering/.
- Stack Overflow and its Stack Exchange sister projects release content under Creative Commons licenses that legally require attribution, yet this material was used for training.
- Purely AI-generated code is not written by a human, so it should not be copyrightable — the Monkey Selfie dispute established that non-humans cannot hold copyrights, a precedent later cited by the U.S. Copyright Office regarding AI.
- Wikimedia Commons already requires purely AI-generated images to be tagged as Public Domain; the same norm could be applied to code.
- Copyright law varies by jurisdiction (e.g., the UK grants limited protection to computer-generated works), so explicitly releasing AI-generated code under Open Source licenses or CC0 is the fairest cross-border solution.
- Code exists on a spectrum between fully manual and fully automated; developers increasingly rely on AI without even reviewing the output, and code where human effort is limited to writing prompts should definitely be Open Source.

* Notes
** The ethical argument: license laundering
- Training corpora for modern [[id:96a58b04-1f58-47c9-993f-551994939252][LLM]] models were assembled by scraping code published under copyleft and permissive licenses, plus Q&A sites governed by Creative Commons terms.
- The author frames closed-sourcing AI output as converting a commons into private property without honoring the original licensing conditions.

** The legal argument: no human authorship
- The *Monkey Selfie dispute* established in the US that non-humans cannot hold copyright; the U.S. Copyright Office extended this reasoning to AI-generated works.
- Wikimedia Commons requires purely AI-generated images to be tagged *Public Domain* — a practical example of the norm the author wants extended to code.
- Jurisdictional inconsistency: some countries (e.g., the UK) grant limited copyright to computer-generated works, so the author proposes an explicit *Open Source license or CC0* dedication to make treatment uniform across jurisdictions.

** Practical implications for developers
- The human-involvement spectrum matters: 100% manual vs. 100% automated code are extremes, but the trend under [[id:d8c9bdbb-4530-4863-bc8a-520d64105270][Agentic Coding]] workflows is toward shipping AI output with little or no review or modification.
- Normative claim: the less human effort beyond prompting, the stronger the obligation to release the result as Open Source.
- Open questions for teams adopting AI coding tools: how to track which portions of a codebase are AI-generated, and how to pick licenses consistent with these provenance obligations.
